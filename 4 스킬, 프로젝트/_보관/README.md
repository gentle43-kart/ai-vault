# _보관 — 스킬·도구의 이전판과 삭제 예정 파일

`4 스킬, 프로젝트/` 안의 스킬·도구 폴더에서 치운 파일을 두는 곳이다(2026-11-27 사용자 요청으로 만듦).
이름이 `_`로 시작하므로 `Claude outputs/skill_catalog.py`는 이 안을 스킬·양식으로 세지 않고, 부록 스크립트 비교에도 쓰지 않는다. `vault_check.py`의 옛 폴더명 검색에서도 빠진다.

| 폴더 | 넣는 것 | 폴더 이름 | 비우는 사람 |
|---|---|---|---|
| `백업/` | 고치기 전의 이전판(다시 볼 수 있어야 하는 것) | `{스킬·도구 폴더 이름}_{YYYY-MM-DD}판/` | 지우지 않는다 |
| `삭제예정/` | 시험 결과물, 필요 없어진 사본 | `{YYYY-MM-DD} {무엇인지}/` | 사용자가 확인한 뒤 직접 지운다 |

- 자료창고의 원본·변환본·위키·스키마 백업은 여기 두지 않는다. 스키마 백업은 `Claude outputs/schema_backup/`, 원본은 `3 source_raw/`가 정해진 곳이다.
- 옮길 때는 스킬의 `CHANGELOG.md`에 "이전판은 `_보관/백업/…`에 있다"처럼 새 위치를 적는다.
- `백업/`은 git에 커밋한다. `삭제예정/`은 `.gitignore`로 빠져 있어 무엇을 넣어도 커밋되지 않는다(2026-11-27). 따로 신경 쓸 필요가 없다.
- 매주 정기 점검(A) 요약에 `삭제예정/`의 항목 수·크기·보관 일수가 나오고, 14일이 넘으면 "비울 때가 됨"으로 강조한다. 비울 때는 Claude에게 "삭제예정 비워줘"라고 하면 목록을 보여 주고 확인을 받은 뒤 휴지통으로 보낸다.
- 다른 곳에 5MB 넘는 새 파일이 생겨도(커밋되지 않은 영상·pptx 등) 같은 요약에 "커밋하지 않을 큰 파일"로 나온다.
