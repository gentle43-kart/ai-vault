# 06. ChatGPT 업무지시서와 비교

비교 대상: 사용자 바탕화면 `방송심의AI프로그램개발업무지시서.md`(ChatGPT 작성, 같은 업무) ↔ 이 폴더의 01~04(automation-spec-builder 시험 결과)
작성: 2026-11-25

## 1. 출발 전제가 다르다

두 문서의 차이 대부분은 품질 차이가 아니라 **입력받은 전제의 차이**다.

| 전제 | ChatGPT 지시서 | 이 설계(01~04) | 근거 |
|---|---|---|---|
| 실행 형태 | 독립 GUI 프로그램(PySide6, 포터블 exe) | 하이브리드(스크립트 + Claude 스킬) | 이 세션의 사용자 답변 |
| AI | 로컬 AI 기본, 외부 API는 승인 후 | Claude만, 로컬 AI 불필요 | 사용자: "로컬AI 필요 없고, 모두 공개 가능" |
| 위반 판단 | AI가 전체 자막을 분석해 위반 가능성 3단계 분류 | 조항·구간·쟁점은 사람이 입력, AI는 판단 안 함 | 사용자: "AI에 모두 판단하도록 자동화하는 것 아님" |
| 보안 | 외부 전송 기본 차단, 승인·미리보기·기록, 키는 Windows 보안 저장소 | 공개 자료라 통제 없음 | 사용자 답변 |
| 저장 | SQLite | 작업 폴더 파일(P2에 SQLite 검토) | 1인·소량 [설계 제안] |

→ 위 항목은 **이 설계에 옮기지 않는다**(사용자 결정과 충돌). 나중에 로컬 AI·보안 통제가 필요해지면 ChatGPT 지시서 2-3절·3절을 그대로 참고하면 된다.

## 3. 이 설계가 더 나은 점 (유지)

- 설치 환경을 실제로 확인했다(한글 13.0 COM 실행, 패키지 버전). 지시서는 "한컴오피스 버전 추후 확인".
- Smoke Test(T1~T5)와 인수 테스트(A·B·C)가 통과 기준과 함께 있다. 지시서는 검수 기준 12개만 있다.
- 미확정 사항을 한 표(03 50절)에 모았다.
- 정보 상태([검증 완료]/[가정]/[TODO])를 구분했다.
- 실패 시 다른 결과를 보존하는 규칙, 동시 실행 방지, 원본 양식 보존 시험이 있다.

## 4. ChatGPT 지시서의 약점 (참고)

- 범위가 넓다(GUI·4개 AI 공급자·SQLite·포터블 배포·전송 승인을 1~6단계에 모두 포함). 우선순위와 1차 제외가 없다.
- 로컬 소형 모델(16GB·내장 그래픽)로 위반 가능성 분석이 쓸 만한 품질인지 검증 계획이 없다.
- 개발 단계마다 완료 기준·시험 방법이 없다.

## 5. 스킬 개선점 (이 비교에서 새로 나온 것)

1. **사용자가 이미 가진 계획·지시서·대화를 먼저 읽고 전제 차이를 표로 보여 줄 것**(이번에는 비교 요청을 받고서야 14개 열을 알았다).
2. **견본 파일이 없어도 구조 정보(열 제목, 양식 항목)는 먼저 묻기.**
3. 표 자료: 원본 열 보존 + 내부 보조 필드 분리 + AI 생성 필드 표시 + 식별자 규칙.
4. 규정·기준 자료: 판단 대상 시점의 판과 현행 판 구분.
5. TO-BE 원칙에 "사람이 자동 결과(전사·초안)를 고치고, 고친 것이 다음 단계 입력이 되며, 이력이 남는다"와 "긴 작업은 중간 저장·이어서 처리"를 추가.
6. 보안이 필요한 경우의 표준 통제(외부 전송 승인·미리보기·기록, 키는 Windows 자격 증명 저장소)를 선택 항목으로 둘 것.
7. 상세 설계서 외에 사람이 읽는 **요약 업무지시서**(2~3쪽)를 결과물로 낼 수 있게 할 것.
