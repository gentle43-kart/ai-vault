## 0. 빠른 입력 (사용자 제공 요약)

```text
업무명: 방송 영상 → 방송심의 안건 초안(HWP)
현재 하는 일: 영상 시청, 쟁점 발언 받아 적기, 장면 캡처, 같은 조항 사례 찾기, 안건양식에 작성
불편한 부분: 받아 적기·캡처·사례 찾기·양식 옮겨 적기에 드는 시간
원하는 결과: 영상과 쟁점을 넣으면 양식이 채워진 HWP 초안
환경·제약: Windows 11, 16GB, 내장 그래픽, Python, 한글. 출력은 HWP만. 로컬 AI 불필요, 자료 공개 가능
```

## 1. 개발 목적

### 1.1 업무 배경 [사용자 확인]
- 방송 영상에서 심의규정 위반 소지가 있는 부분을 확인해 안건으로 올린다.
- 안건은 한글 양식(유형별 여러 종)으로 작성한다.

### 1.2 문제점 [가정]
- 쟁점 구간 발언을 손으로 받아 적어 시간이 들고 오기가 생긴다.
- 장면 캡처와 시각 기록을 손으로 한다.
- 같은 조항의 과거 의결을 찾는 데 시간이 든다.
- 정리한 내용을 양식에 다시 옮겨 적는다.

### 1.3 자동화 목표
담당자가 **영상 + 조항·구간·쟁점**을 주면, 쟁점 구간 전사·캡처·유사 사례가 정리되고 그것을 바탕으로 쓴 초안이 **선택한 HWP 양식에 채워져 저장**된다. 위반 여부 판단은 하지 않는다.

### 1.4 핵심 사용 방식
```text
담당자: "이 영상으로 안건 만들어줘" + 조항·구간·쟁점
   ↓ (Claude 스킬이 입력 확인)
스크립트: 구간 전사 + 구간 캡처 + 사례 검색 → output 폴더에 저장
   ↓
Claude: 전사·캡처·사례·규정을 읽고 초안(MD) 작성 → 담당자 확인·수정
   ↓
스크립트: 확정 초안을 HWP 양식에 입력 → HWP 저장
```

## 2. 현재 업무 흐름(AS-IS)

| 단계 | 현재 작업 | 입력 | 출력 | 사람 판단 | 자동화 |
|---|---|---|---|---|---|
| 1 | 영상 시청, 쟁점·조항 결정 | 영상 | 메모 | 필요 | 유지(사람) |
| 2 | 쟁점 발언 받아 적기 | 영상 | 발언 메모 | 불필요 | 자동화 |
| 3 | 장면 캡처 | 영상 | 이미지 | 장면 고르기 | 자동화(간격 캡처) + 사람 선택 |
| 4 | 같은 조항 사례 찾기 | 의결 내역 | 사례 목록 | 비슷한지 판단 | 규칙(검색) + 사람 |
| 5 | 방송내용·적용 사유 작성 | 2~4 | 문장 | 필요 | AI 보조 |
| 6 | 양식에 옮겨 적기 | 문장 | HWP | 불필요 | 자동화 |
| 7 | 검토·수정 | HWP | 최종 안건 | 필요 | 유지(사람) |

## 3. 목표 업무 흐름(TO-BE)

```text
담당자 입력(영상·조항·구간·쟁점·양식 종류)
   ↓
[스크립트] 구간 음성 → 전사 JSON/SRT  (실패해도 캡처는 계속)
[스크립트] 구간 캡처 PNG
[스크립트] 사례 CSV에서 조항·키워드 검색 → 후보 표
   ↓  (모두 output\<작업ID>\에 저장)
[Claude] 판독 + 초안 MD(방송내용·적용 사유·사례 대조) — 결론 없음
   ↓  담당자 확인·수정
[스크립트] 초안 MD → 양식 HWP 입력 → 저장
```

원칙: 영상 전체를 AI에 넣지 않는다. 스크립트 결과는 AI와 무관하게 먼저 저장한다. 과거 의결 결론을 정답처럼 옮기지 않는다.

## 4. 자동화 범위

### 4.1 1차(P0) — 반드시 구현
- 작업 입력 파일(`job.json`) 만들기: 영상 경로, 조항, 구간, 쟁점, 양식 종류
- 구간 전사(faster-whisper) → `transcript.json`, `transcript.srt`
- 구간 캡처(FFmpeg) → `frames\`
- 초안 MD 형식 정의와 Claude 작성 절차(스킬)
- HWP 양식 1종 채우기 → `안건_<작업ID>.hwp`

### 4.2 2차(P1·P2) 후보
- P1: 양식 여러 종과 양식 선택, 사례 CSV 검색, 인용 발언 타임코드 대조표, **전사 수정본**(담당자가 `transcript_edited.json`을 고치면 이후 단계는 수정본을 씀) [06 R6]
- P2: 엑셀 → CSV 갱신(중복 확인·변경 기록), 긴 영상 전체 전사 옵션(10분 단위 분할·중간 저장·이어서 처리) [06 R7], 캡처 격자 한 장 보기

### 4.3 개발 제외
- 위반 여부 자동 판단, 조항 자동 선정
- 로컬 AI·모델 선택
- 화면 글자 인식(OCR)
- 여러 영상 일괄 처리, 별도 GUI 프로그램

## 10. 외부 데이터 연동 구성

### 연동 ① 한글(HWP) 양식 입력
- 목적: 초안 내용을 양식의 지정 위치에 넣고 새 이름으로 저장
- 방식: `HWPFrame.HwpObject` COM. 1안 누름틀 필드 이름으로 입력, 2안 표의 특정 칸으로 이동해 입력 [설계 제안]
- 내부 인터페이스:
  ```python
  def fill_template(template_path: Path, values: dict[str, str], out_path: Path) -> FillResult: ...
  ```
- 미확정: 양식에 누름틀이 있는지, 칸 위치 규칙, 여러 문단·표 안 줄바꿈 처리 [TODO]

### 연동 ② 음성인식(faster-whisper)
- 내부 인터페이스:
  ```python
  def transcribe(video: Path, start: float, end: float, model: str = "medium") -> list[Segment]: ...
  ```
- 구간 앞뒤 5초 여유를 두고 인식한 뒤 구간 안 문장만 남긴다 [설계 제안]

### 연동 ③ 사례 CSV
- 내부 인터페이스: `search_cases(article: str, keywords: list[str], limit=10) -> list[Case]`
- 원본 열(14개) [사용자 확인 — ChatGPT 지시서 4-1에 사용자가 준 열 제목]: 순번, 의결일, 의결번호, 방송사, 채널명, 프로그램명(방송일시), 의결 내용, 관련조항, 심의결과, 인지방법, 부서, 통계부문, 비고, 민원 총건수
- 읽기: xlsx·csv 모두, 인코딩 UTF-8·UTF-8 BOM·CP949 순서로 시도. 열 이름이 다르면 `config.json`의 열 매핑으로 맞춘다.
- 미확정: 관련조항 칸의 실제 표기 형식(예: "방송심의규정 제27조 제5호" 여부), 프로그램명(방송일시) 분리 규칙 [TODO — 실제 파일 필요]

## 11. Adapter 설계 원칙

한글 COM, 사례 CSV의 원래 열 이름은 각각 `adapters\hwp.py`, `adapters\cases_csv.py` 밖으로 나오지 않는다. 나머지 코드는 12절의 내부 모델만 쓴다.

## 12. 내부 표준 데이터 모델

```python
@dataclass
class Job:            # job.json
    job_id: str       # 예: 20261125_프로그램명
    video: Path
    article: list[str]        # ["방송심의규정 제27조 제5호"] 사용자 입력
    ranges: list[tuple[float, float]]  # 쟁점 구간(초)
    issue: str                # 쟁점 설명(위반 소지·반론 소지)
    template: str             # 양식 종류 키
    meta: dict                # 방송사·프로그램·방송일시(선택)

@dataclass
class Segment:  start: float; end: float; text: str
@dataclass
class Frame:    t: float; path: Path
@dataclass
class Case:                       # 원본 14열에서 Adapter가 만듦
    internal_id: str              # 의결번호, 없거나 중복이면 "X-<파일>-<순번>"
    case_no: str | None           # 의결번호
    decided_at: str | None        # 의결일
    broadcaster: str | None; channel: str | None
    program_raw: str | None       # 프로그램명(방송일시) 원문 그대로
    program_name: str | None; broadcast_datetime: str | None   # 분리값(분리 실패 시 None)
    decision_text: str | None     # 의결 내용(원문)
    article_raw: str | None       # 관련조항(원문)
    regulation_ids: list[str]     # 관련조항에서 뽑은 "제n조" 목록
    result: str | None            # 심의결과
    source_file: str; import_date: str
```
- 원본 14열은 손대지 않고, 위의 분리값·`regulation_ids`만 내부 보조 필드로 만든다. AI가 만든 요약·분류 필드는 1차에 두지 않는다(두게 되면 `ai_` 접두어로 원본과 구분) [06 R2].

## 13. 데이터 검색 규칙

- 사례: 1차 조항 일치(사용자 입력 조항), 2차 쟁점 키워드(제목·위반내용 열), 최근 의결 우선, 최대 10건
- 키워드는 `job.json`의 `issue`에서 사용자가 지정한 것만 쓴다(자동 확장 안 함) [설계 제안]
- **조문 시점:** 규정 조문은 **방송일 당시 판**으로 가져온다. 사례는 의결 당시 조 번호로 적혀 있으므로, 조 번호가 바뀐 경우(개정으로 조 번호 변경) 대응표로 맞춰 검색하고, 초안에는 "사례 당시 조항"과 "현재 안건 적용 조항"을 따로 적는다 [06 R4]. 규정 MD에는 front matter로 시행일·버전을 두고 `amendment_history.md`에 대응표를 둔다.

## 14. 결과 통합 및 중복 제거

- 사례 고유키: 의결번호. 없거나 파일 안에서 중복이면 내부 번호(`X-<파일>-<순번>`)를 주고 중복 목록을 `cases_import_log.txt`에 남긴다 [06 R3]
- 전사 구간이 겹치면 시작 시각 기준으로 합친다.

## 15. 관심 대상 필터링

조항·구간·쟁점은 사람이 정하므로 AI 필터링은 하지 않는다. 사례 검색은 규칙(조항·키워드)만 쓴다.

## 16. 데이터베이스 설계

해당 없음 — 1차는 DB 없이 파일로 관리한다(작업 수가 적고 한 사람이 씀). 작업별 폴더가 이력 역할을 한다. 사례가 많아 검색이 느리면 P2에서 SQLite로 바꾼다.

## 17. 원본 데이터 저장 정책

- 영상 원본은 복사하지 않고 경로만 `job.json`에 적는다.
- 의결 내역은 원본 xlsx를 그대로 두고 변환 CSV만 읽는다.
- 개인정보: 일반 출연자 실명이 전사에 들어갈 수 있음 → 초안에서 일반인 실명은 쓰지 않는다(심의 안건 관행) [가정, 확인 필요].

## 18. 데이터 변경 감지

- 같은 작업을 다시 실행하면 `job.json`의 영상 경로·구간이 같고 결과 파일이 있으면 전사·캡처를 건너뛴다(`--force`로 다시 실행).
- **사람이 고친 결과 우선:** `transcript_edited.json`이 있으면 이후 단계(context·draft)는 수정본을 쓰고, `--force`로 다시 전사해도 수정본은 지우지 않는다(P1) [06 R6].
- 사례 CSV는 파일 수정 시각이 바뀌면 다시 읽고, 건수 변화(추가·중복·누락)를 `cases_import_log.txt`에 날짜와 함께 남긴다 [06 R9].

## 19. AI 적용 여부 및 호출 정책

| AI 사용 | AI 사용 안 함 |
|---|---|
| 쟁점 구간 전사·캡처 판독 | 전사, 캡처, 사례 검색, 양식 입력 |
| 방송내용·적용 사유 문장 초안 | 조항·구간 결정, 위반 여부 판단 |
| 사례와의 같은 점·다른 점 정리 | 중복 제거, 날짜 처리 |

AI는 담당자가 요청할 때만 쓴다(대화 안). 같은 작업의 초안을 다시 쓰면 이전 초안을 `draft_v1.md`처럼 남긴다.

## 26. 처리 실행(prepare)

- 진행 상황은 콘솔과 `output\<작업ID>\log.txt`에 적는다.

## 27. 진행 상태

콘솔 출력 예: `[1/4] 전사 12:40~13:30 … 완료(1분 52초)` / `[2/4] 캡처 26장` / `[3/4] 사례 7건` / `[4/4] context.md 작성`

## 33. 파일별 구현 요구사항

- `agenda.py`: 명령 해석, 작업 폴더 생성, 단계 호출, 종료 코드(0 성공, 1 일부 실패, 2 입력 오류)
- `core/transcribe.py`: 구간 ±5초 인식 후 구간 안만 저장, JSON·SRT 동시 저장, 소요 시간 기록
- `core/frames.py`: FFmpeg로 구간·간격 캡처, 파일명 시각 표기, 최대 장수 제한
- `core/context.py`: 21절 형식으로 context.md 작성
- `adapters/hwp.py`: 양식 복사본을 열어 입력 → 저장 → 스크립트가 띄운 한글만 종료. 원본 양식은 열기 전용
- `adapters/cases_csv.py`: 원본 열 이름 → `Case` 변환, 조항 표기 정규화
- `adapters/regulations_md.py`: 조항 번호로 MD 파일 찾기

## 52. 유지보수 원칙

양식 추가는 `template_config.json`만 고친다. 엑셀 열이 바뀌면 `config.json`의 열 매핑(또는 `cases_csv.py`)만 고친다. **프로그램 갱신과 자료 갱신을 분리한다:** 코드는 도구 폴더, 자료(사례·규정·양식)는 `data\`에 두어 자료만 바꿔도 코드를 건드리지 않는다 [06 R8]. 스킬 지시를 바꾸면 SKILL.md와 CHANGELOG를 함께 고치고 카탈로그를 갱신한다.

## 53. 개발용 AI에 대한 구현 지시

1. 확정 요구와 50절 TODO를 구분한다. TODO에 걸린 기능은 견본을 받기 전에 구현하지 않는다.
2. 한글 양식 구조·CSV 열 이름을 추측해서 코드에 넣지 않는다.
3. 구현 전에 T1·T2(그리고 견본이 오면 T3·T4)를 실제로 실행한다.
4. 한글 COM과 CSV 원본 열 이름은 adapters 밖으로 내보내지 않는다.
5. 전사·캡처 실패, 한글 실패가 다른 결과물 저장을 막지 않게 한다.
6. 실제 담당자 흐름(28절)대로 견본 영상 1건을 끝까지 돌려 본다.
7. `.cmd`는 새 CMD 창에서 실행해 확인한다.
8. 시험하지 않은 것은 완료라고 쓰지 않는다.
