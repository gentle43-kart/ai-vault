# 방송 영상 → 심의안건 방송내용 초안

도구 폴더: `J:\AI 자료\4 스킬, 프로젝트\유튜브스크립트` (AGENTS.md 2절상 Claude는 읽기만. 아래 실행으로 `output\`에 결과가 생기는 것은 사용자가 승인한 사용 방식이다. 스크립트·README 수정은 사용자 지시가 있을 때만.)

**핵심:** 방송내용은 그 방송이 위반 조항에 어떻게 저촉되는지를 구체적으로 보여주도록 쓴다. 영상 전체를 차례로 옮기지 않는다. 서술 형식은 고정하지 않고 비슷한 유형의 안건 예시를 찾아 따른다. 작성 범위는 프로그램 개요·방송내용·적용조항(사유+조항)까지. 상세 규칙은 [references/서술규칙.md](references/서술규칙.md).

## 1. 입력 확인
- **필수:** 영상 경로, ① 위반 조항(대부분 「방송심의에 관한 규정」 제○조 제○항 제○호. **복수일 수 있다**) ② 영상 중 관련 부분(시각이나 장면 설명) ③ 쟁점(위반 소지가 있어 보이는 내용, 반론 소지가 있는 부분). 빠진 것이 있으면 영상 실행(2단계)은 먼저 시작하되, 초안 작성(5단계) 전에 묻는다.
- 조항을 아직 못 정했거나 "네가 잡아 봐라"라고 하면 임의로 하나를 골라 쓰지 않는다. 방송 내용을 근거로 **후보 2~3개**를 내고, 후보마다 해당 가능성이 있는 대목과 반론 소지가 될 대목을 1줄씩 적은 뒤 선택을 요청한다. 결론(위반 여부)은 쓰지 않는다.
- **선택:** 방송사·프로그램·방송일시·유형, 인지구분(심의신청/모니터), 심의신청 취지, 인물 정보(실명·직함·역할. 화자가 구분된 외부 전사본이면 화자 매핑), 사용자가 가진 전사본(클로바노트 등). 없으면 [확인 필요].
- **긴 영상(대략 20분 이상)은 먼저 경로 안내에 따라 ②로 할지 확인한다.** 사용자가 이 스킬(①)을 고르면 2단계의 '긴 영상' 절차를 따른다. 구간(시각)을 모르면 먼저 묻는다.

## 2. 영상 실행 (PowerShell, Python 3.12)
```powershell
cd 'J:\AI 자료\4 스킬, 프로젝트\유튜브스크립트'
py -3.12 video_to_draft.py "<영상 경로>"
```
- 기본: medium 모델, ko, 최대 간격 4초, 장면 전환 임계값 30. CPU에서 영상 길이와 비슷하거나 더 걸린다. 10분 넘는 영상은 백그라운드로 실행하고, 그동안 3단계를 한다.
- 같은 이름의 출력 폴더가 있으면 멈춘다. 덮어써도 되는지 사용자에게 묻고 `--force`.
- `metadata_errors` 오류 → av 19.x가 설치된 것. 사용자에게 설명하고 승인받은 뒤 `py -3.12 -m pip install "av<19"`.
- 프레임이 너무 많으면(분당 40장 이상) `--scene-threshold 40` 또는 `--interval 6`, 쟁점 구간의 자막이 빠지면 `--interval 2`로 다시 실행을 제안한다.
- 옵션(v2): `--start`·`--end`(초, 분:초, 시:분:초)로 구간만 처리한다. 프레임은 그 위치로 건너뛰어 읽고 Whisper도 구간만(앞뒤 5초 여유, 최소 30초 단위로 인식한 뒤 구간 안만 남김) 인식한다. 출력 폴더 이름에 `_구간HH-MM-SS~HH-MM-SS`가 붙어 전체 처리 결과를 지우지 않는다. `--transcript <파일>`은 클로바노트 등 외부 전사본(txt·srt)을 읽고 Whisper를 건너뛴다.
  - 외부 전사본 형식: ① `참석자 1 00:03` 줄 + 다음 줄들의 본문, ② `[00:00:03] 본문`, ③ SRT. 시각이 없는 형식은 거부한다. 화자 표기는 서비스 값 그대로 `timeline.md`에 들어가고, 끝 시각이 없어 발화 길이는 다음 발화 시작(최대 15초)까지로 본다. 클로바노트 실제 내보내기 파일로는 아직 시험하지 못했으므로 처음 쓸 때 `timeline.md`의 전사가 맞게 붙었는지 확인한다.

### 긴 영상(대략 20분 이상) 절차 — 토큰·시간 절약
기본값으로 전체를 돌리면 CPU Whisper가 영상 길이의 1.3~2배 걸리고, 프레임 상한(200장) 때문에 1시간 영상은 프레임 간격이 18~36초로 벌어져 몇 초짜리 쟁점 장면을 놓친다. 그래서:
1. 사용자에게 **쟁점 구간 시각**을 받는다. 모르면 전사본(사용자 것이 있으면 그것, 없으면 아래 2번)을 훑어 후보 구간을 제안하고 확인받는다.
2. 사용자 전사본이 없으면 전체 전사를 **백그라운드**로 돌린다(`--no-transcribe` 없이 전체 실행은 시간이 오래 걸린다고 알린다). 사용자 전사본이 있으면 `--transcript`로 건너뛴다.
3. 쟁점 구간 ± 1~2분만 `--start --end`로 추출한다. 동작이 쟁점이면 같은 구간을 0.5초 간격으로 다시 뽑는다(4단계).
4. 영상 전체 개요가 필요하면 `--interval 60 --width 480`으로 뽑아 격자 한 장(24장)으로만 본다. 프레임을 낱장으로 수십 장 읽지 않는다.
5. 초안에는 처리한 구간을 밝히고, 그 밖은 확인하지 않았다고 적는다.
6. 작업 중 토큰이 부족해지면 `timeline.md`와 쟁점 프레임까지만 만들고 초안 작성은 ② '안건 작성' 프로젝트로 넘길 수 있다고 사용자에게 알린다.

## 3. 유사 안건 예시·같은 조항 사례 찾기 (참고용)
목적은 ① 이 영상과 유형이 비슷한 안건의 **서술 형식**을 정하고(서술규칙 2절) ② 같은 조항 안건이 문제 장면과 적용 사유를 **어떻게 서술했는지** 참고하는 것이다. 결론·제재 수위를 끌어오지 않는다.
- 먼저 유형을 정한다: 프로그램 유형 × 쟁점이 있는 곳(화면/발언/자막/편집) × 조항.
- 유형별 안건 작성 예시(사용자가 위키 소스자료에 넣는 것)가 있으면 그것부터 본다. 예시 색인 `J:\AI 자료\0 wiki\분석\안건 작성예시 색인.md`(2009~2014년 유형별 안건 모음 115개, 대구사무소 안건 2023~2026년 8건, 예시1~3·2026년 회의자료 안건 79건, 쟁점 폴더별 표에서 `적용조항` 열로 같은 조항을 찾는다)로 바로 찾고, 예시1~3과 2026년 회의자료는 `0 wiki\쟁점\심의안건 작성 방식.md` 8절 색인표에서 찾는다.
- 예시는 1~2건만 정독한다. 후보가 많으면 제목·조항으로 고르고 본문을 다 읽지 않는다.
- 방송일 당시 조 번호를 확인한다. 2026.9.29. 이후 조 번호가 바뀌었으니 `J:\AI 자료\0 wiki\분석\조문 시기 대응표.md`로 대조한다.
- 위키: `0 wiki\조문\_index.md`에서 해당 조문 페이지, `0 wiki\사례\_index.md`에서 같은 조항 사례, `0 wiki\쟁점\심의안건 작성 방식.md`와 `1 documents_md\작성예시_md\안건\`의 예시·2026년 회의자료에서 같은 조항 세부안건을 찾는다.
- 검색: MCP `ai-vault`의 `search`(kind `wiki|minutes|cases`, 조항 이름·쟁점 키워드), 의결 내역은 `query_decisions`(unit=case, article, 필요하면 content 키워드·`article_basis`), 의결번호 상세는 `search_case`.
- 보도 유형·쟁점이 비슷한 사례 2~4건을 고른다. 기사·논문은 공식 자료가 아니다. 보안등급 [internal] 자료는 초안 안에서 출처만 밝힌다.

## 4. 판독
- `output\<영상이름>\timeline.md`를 읽고, `frames\`의 PNG를 본다(Read 도구). 쟁점 구간은 모든 프레임을, 나머지는 범위 확인에 필요한 만큼 본다.
- 쟁점 구간의 자막(제목·이름·인용 자막), 화면 구도, 흐림·음성변조 처리, 노출 시간을 적어 둔다. 판독이 불확실하면 `[확인 필요: 00:01:23 자막 판독]`.
- 앞뒤 다른 보도·광고·예고 화면을 찾아 이 안건의 범위(시작~끝 시각)를 정한다.
- **동작이 쟁점인 장면(폭력·사고·선정적 동작 등)은 0.5초 간격으로 다시 뽑는다**(묻지 않고 진행. 출력은 임시 폴더):
  `py -3.12 video_to_draft.py "<영상>" -d "<스크래치패드>\dense" --no-transcribe --interval 0.5 --min-gap 0.5 --width 480 --force`
  긴 영상이면 쟁점 구간만: 위 명령에 `--start 00:12:40 --end 00:13:10`을 붙인다(구간 밖 전체를 0.5초 간격으로 뽑지 않는다).
  프레임이 많으면 쟁점 구간 프레임을 4열 격자 한 장(24장씩)으로 묶어 보면 빠르다(Pillow 사용, 각 칸에 파일명 표시).
- 클로즈업·반복 노출·재방송 등 편집 구성을 확인한다. 빠른 동작의 횟수는 정지 화면으로 단정하지 않고 [확인 필요]로 둔다.

## 5. 초안 작성
- 서술 규칙: [references/서술규칙.md](references/서술규칙.md). 시범 단계이며 사용자가 다듬는 중이다. 규칙 파일이 바뀌었으면 그 내용을 우선한다.
- 저장: `output\<영상이름>\방송내용_초안.md`. 이미 있으면 덮어쓰지 말고 `방송내용_초안_2.md`처럼 번호를 붙인다.
- 구성:
  1. 가. 프로그램 개요
  2. 나. 방송내용: 쟁점 중심, 반론 소지 포함, 시간순. 형식은 3단계에서 고른 예시를 따른다(없으면 서술규칙 3절)
  3. 적용조항: "○ … 점을 고려함." + "○「방송심의에 관한 규정」제○조(…)제○항"(서술규칙 4절)
  4. <방송화면> 후보 표(번호·시각·프레임 파일·선정 이유 1줄. 쟁점 장면 우선, 반론 소지 장면도 고려). 본문에는 해당 장면 끝에 `(<방송화면1, 2> 참조)`를 적는다(사용자 결정 2026-11-22). 개수는 고정하지 않는다: 시각 정보(자막 문구, 구도, 노출·흐림 정도, 인물 특정 가능성)가 있는 장면만 뽑고, 발언은 본문 인용으로 충분하다. 본문 항목 수에 맞추지 않는다. 여러 방송일은 일자마다 최소 1장(같은 장면 반복이면 대표 1장). 사용자가 개수·장면을 정했으면 그대로 따른다. 선정 사유를 못 쓰는 장면은 뺀다.
  5. 작성 참고(안건 본문에 넣지 않음): 따른 서술 형식의 예시와 이유, 같은 조항 사례(의결번호·방송사·프로그램, 참고한 점, 출처 위치)
  6. **조항 커버리지**(안건 본문에 넣지 않음): 위반 조항이 복수면 조항마다 뒷받침하는 본문 항목을 1줄로 대조한다(`제45조 → 항목 2·3 (… 장면)`). 뒷받침 장면이 없는 조항은 "뒷받침 장면 없음, 해당 장면 추가 확인 필요"로 적고 조용히 넘기지 않는다. 사용자가 준 조항 밖에서 쟁점이 보이면 `[포착된 쟁점]`으로 한 줄 알린다(조항을 임의로 바꿔 쓰지 않는다). 서술해 보니 조항으로 보기 어려운 사안이면 초안과 함께 그 사실을 1~2줄로 지적하고 사용자와 논의한다.
  7. 검토 체크리스트(시각·항목·내용): 화자 추정, 판독 불확실, 사용자 쟁점 중 영상에서 확인되지 않은 부분, 조 번호 판(방송일 기준) 확인, 정지·스킵·반복 같은 편집 구성 주장 중 원 영상 대조가 필요한 것

- 참고사항·붙임·심의 결론(제재 수위)을 쓰지 않는다. 방송내용에는 판단이 담긴 표현("선정적인", "부적절한")을 넣지 않는다. 적용조항 사유 문장은 사용자가 준 쟁점 범위 안에서만 쓴다.
- 사례의 제재 수위를 이 안건의 결론처럼 쓰지 않는다.
- 영상·전사본·초안을 `J:\AI 자료`의 다른 폴더(0 wiki, 1 documents_md 등)에 넣지 않는다(사용자가 요청할 때만, AGENTS.md 절차에 따라).
- `video_to_script.py`의 동작·출력 형식을 바꾸지 않는다(채팅의 유튜브 스크립트 스킬이 전제로 함).
