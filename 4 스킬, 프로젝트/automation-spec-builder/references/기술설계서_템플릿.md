# 범용 업무 자동화 시스템 상세 기술설계서 템플릿

**문서 용도:** 업무 자동화 아이디어를 실제 개발 가능한 기술설계서로 전환하기 위한 범용 템플릿  
**권장 사용 방식:** 사용자는 업무 설명 몇 줄만 제공하고, AI가 본 템플릿을 채우되 미확정 정보는 추정하지 않고 `확인 필요` 또는 `TODO`로 표시한다.  
**권장 산출물 수준:** 개인·팀 단위 Local/Web 자동화, API 연동, 데이터 수집, LLM 활용 프로그램의 1차 개발 명세

---

# 0. 빠른 입력 — 사용자가 최소한으로 적을 내용

아래 5개 항목만 있어도 설계 작업을 시작할 수 있다.

```text
업무명:
현재 하는 일:
가장 반복적이거나 불편한 부분:
원하는 최종 결과:
사용 환경 또는 제약:
```

선택적으로 아래 내용을 추가하면 설계 정확도가 높아진다.

```text
업무 빈도: 매일 / 매주 / 수시 / 월 1회 등
입력 데이터: 웹사이트 / API / 이메일 / 엑셀 / PDF / 사내시스템 / 직접 입력 등
결과물 형태: 웹 화면 / 엑셀 / 보고서 / 알림 / 이메일 / 파일 저장 등
사용자 수: 1명 / 팀 / 조직
실행 방식: 버튼 클릭 / 자동 실행 / 예약 실행 / 조건 충족 시 실행
보안 요구: 개인정보 / 사내자료 / 인증 필요 여부
AI 필요성: 요약 / 분류 / 판단 보조 / 문안 작성 / 불필요
```


```sql
CREATE TABLE main_items (
    item_id TEXT PRIMARY KEY,
    title TEXT,
    category TEXT,
    status TEXT,
    source_url TEXT,
    source_hash TEXT,
    first_seen_at DATETIME NOT NULL,
    last_checked_at DATETIME,
    created_at DATETIME NOT NULL,

```

## 16.2 item_keywords 또는 item_tags

```sql
CREATE TABLE item_keywords (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    item_id TEXT NOT NULL,
    keyword TEXT NOT NULL,
    created_at DATETIME NOT NULL,
    UNIQUE(item_id, keyword)
);
```

## 16.3 summaries

```sql
CREATE TABLE summaries (
    id INTEGER PRIMARY KEY AUTOINCREMENT,

    source_hash TEXT NOT NULL,
    created_at DATETIME NOT NULL,
```

```sql
CREATE TABLE sync_logs (
```

# 18. 데이터 변경 감지

주요 내용을 조합해 SHA-256 등으로 해시를 생성한다.

```python
source = "|".join([
    item.title or "",
    item.status or "",
    item.detail_content or "",
])
```

```text
기존 hash == 신규 hash
        ↓
변경 없음
        ↓
기존 처리 결과 재사용
```

```text
기존 hash != 신규 hash
        ↓
변경 있음
        ↓
필요한 후속 처리 재실행
```

# 19. AI/LLM 적용 여부 및 호출 정책

## 19.1 AI를 사용할 작업

```text
- 요약
- 분류
- 중요도 보조판단
- 문안 생성
- 비교 설명
```

## 19.2 AI를 사용하지 않을 작업

```text
- 단순 중복 제거
- 날짜 비교
- 정확한 수치 계산
- 명확한 규칙 기반 필터
```

## 19.3 호출 최소화 정책

```text
신규 또는 변경 데이터 → AI 호출
기존 데이터 + 변경 없음 → 기존 결과 재사용
수동 재처리 → 강제 AI 호출
```

# 53. 개발용 AI에 대한 구현 지시

이 문서를 입력받은 개발용 AI는 다음 원칙을 지킨다.

1. 문서에서 확정된 요구사항과 미확정 사항을 구분한다.
2. 외부 API의 실제 명세가 확인되지 않은 부분을 임의로 추정하지 않는다.
3. 구현 전에 핵심 외부 연동을 Smoke Test한다.
4. 원본 데이터 저장과 AI 처리를 분리한다.
5. 단위 테스트뿐 아니라 실제 사용자 실행 시나리오를 검증한다.
6. Windows 실행 프로그램이면 `run.bat`을 실제 CMD 기준으로 검증한다.
7. 개발 완료 후 소스코드만 제공하지 말고 실행 가능한 ZIP과 README를 제공한다.
8. 테스트하지 못한 항목은 `검증 완료`라고 표현하지 않는다.
