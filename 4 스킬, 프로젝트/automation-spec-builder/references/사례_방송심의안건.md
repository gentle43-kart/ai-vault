# 사례: 방송 영상 → 심의 안건 초안 자동작성 계획

출처: 사용자가 ChatGPT와 나눈 설계 대화(2026-11-25 공유 링크, 질문 4회·답변 4회)를 이 스킬의 단계에 맞춰 정리한 것. 대화 원문을 옮긴 것이 아니며, 당시 답변 가운데 확인되지 않은 주장은 `[가정]`으로 표시했다.

## 대화 흐름과 스킬 단계

| 차례 | 사용자 입력 | 정해진 것 | 스킬 단계 |
|---|---|---|---|
| 1 | 영상을 넣으면 심의규정 위반 내용을 찾아 안건양식을 채우고 싶다. 영상은 faster-whisper로 자막을 먼저 뽑는다. Python 설치됨 | 처리 흐름: 영상 → 음성 추출(FFmpeg) → 전사(타임코드 포함) → 의심 구간 탐색 → 규정·사례 대조 → 양식 작성 → 검증. 필요한 기준 자료: 규정, 심의사례, 양식, 완성 안건 2~3건 | 1단계 문제 정의 |
| 2 | Claude·ChatGPT 안에서 돌릴지 독립 프로그램으로 할지? 독립이면 모델 선택(로컬 AI 포함) 가능해야 | 독립 프로그램 + 작업별 모델 지정(Adapter: OpenAI·Claude·Gemini·Ollama). 전사·검색은 로컬, 복잡한 판단·작성은 상용 API, 검수는 다른 모델 | 3단계 실행 형태 |
| 3 | Windows 11, Intel 내장 그래픽, RAM 16GB, 문서는 한글(HWP)만 | 하이브리드 AI. CPU 기준, 로컬 LLM은 1.5B~4B 양자화부터 시험. Whisper는 CPU int8, 한국어 고정, SRT+JSON. 출력은 한글 COM으로 기존 HWP 양식에 입력(python-docx 기각). 16GB 원칙: 모델 하나씩 실행, 긴 자막은 나눠 분석, 중간 결과 저장 | 2단계 환경 확정 |
| 4 | 사례는 의결내역 엑셀→CSV, 규정은 MD, 한글 양식은 여러 개로? | 그대로 채택. CSV는 원본 보존+변환, 결론(의결결과)과 이유(의결이유) 분리. 규정은 조항별 MD+front matter(조항·시행일·버전), 원문과 AI 판단요소 분리, 개정 이력 구분. 양식은 유형별 HWP 여러 개+template_config.json, 양식은 추천하되 담당자가 선택. 신규 엑셀 추가 시 자동 갱신 절차 | 5단계 자료 형식 |

## 이 사례에서 얻은 규칙(스킬 본문에 반영함)

1. **출력 형식을 먼저 물어야 한다.** 1·2차 답변은 출력 형식을 모른 채 python-docx를 추천했고, HWP만 쓴다는 답을 듣고 나서야 한글 COM으로 바꿨다.
2. **사양을 알고 나서 로컬 AI 범위를 정한다.** 16GB·내장 그래픽이면 소형 모델부터 측정하고, 복잡한 판단은 상용 API로 넘긴다.
3. **AI는 판단을 확정하지 않는다.** 위반 `가능성 높음 / 추가 검토 / 가능성 낮음`으로 나누고, 과거 의결을 정답처럼 복사하지 않으며, 실제 방송 내용·당시 규정·사례와의 차이를 함께 보여 준다.
4. **음성만으로는 부족하다.** 화면 자막·장면은 해당 시간대 캡처(필요하면 OCR·비전 모델)로 따로 확인한다.
5. **기존 도구를 먼저 확인했어야 한다.** 이 PC에는 이미 `video_to_draft.py`(전사+캡처+타임라인)와 `broadcast-content-draft` 스킬이 있다. 같은 업무를 다시 계획한다면 새 프로그램이 아니라 이 도구의 확장으로 계획한다.
