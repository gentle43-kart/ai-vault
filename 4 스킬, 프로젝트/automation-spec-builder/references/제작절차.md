# 제작 절차 (계획서 확정 후 실제로 만들기)

사용자가 계획서를 확인하고 "만들어줘", "개발 시작해" 같이 제작을 요청했을 때 따른다. 계획서 없이 바로 제작을 요청하면 최소한 Quick 모드 브리프와 P0 범위를 먼저 정하고 확인을 받는다.

---

## B0. 착수 조건 확인

다음이 모두 맞아야 시작한다. 하나라도 빠지면 그것부터 해결한다.

- 실행 형태(스킬·독립 프로그램·하이브리드)와 P0 범위가 확정되어 있다.
- P0를 막는 `[TODO]`가 없다. 입력 자료 견본, 출력 양식, 외부 연동 정보가 여기에 해당한다.
- 도구 이름(폴더명)이 정해져 있다. 영문 소문자와 하이픈, 또는 사용자가 정한 한글 이름을 쓴다.

## B1. 작업 나누기와 제작 기록

P0를 한 번에 확인할 수 있는 작은 작업으로 나누고, 설계 폴더에 `05_제작기록.md`를 만든다.

```markdown
# <업무명> 제작 기록

도구 폴더: J:\AI 자료\4 스킬, 프로젝트\<도구명>\
설계 문서: J:\AI 자료\4 스킬, 프로젝트\<도구명>\설계\03_상세기술설계서.md

| 번호 | 작업 | 완료 기준 | 상태 | 시험 결과·날짜 |
|---|---|---|---|---|
| P0-1 | 입력 파일 읽기 | 견본 3건을 오류 없이 읽음 | 완료 | 2026-11-25 견본 3/3 |
| P0-2 | ... | ... | 진행 중 | |

## 결정·변경
- 날짜: 내용(이유)

## 남은 문제
- 
```

- 상태는 `대기 / 진행 중 / 완료 / 보류(이유)` 중 하나로 적는다.
- 작업 목록은 update_plan의 작업 목록과 맞춘다.
- 세션이 바뀌면 이 파일부터 읽고 이어간다. 사용자가 인계메모를 요청하면 이 파일을 근거로 쓴다.

## B2. 도구 폴더 만들기

위치는 `J:\AI 자료\4 스킬, 프로젝트\<도구명>\`이다. J 루트에는 새 폴더를 만들지 않는다. 기본 구성은 아래와 같고, 필요 없는 것은 만들지 않는다.

```text
<도구명>/
├── <도구명>.py           핵심 스크립트(여러 개면 기능별로 나눔)
├── <도구 이름>.cmd        사용자가 더블클릭으로 실행하는 파일
├── config.example.json    설정 예시(실제 설정 config.json은 사용자가 복사해 수정)
├── .env.example           API 키 이름만 적은 예시(값 없음)
├── INPUT\  OUTPUT\        입출력 폴더(필요할 때)
├── tests\                 시험 스크립트와 견본 자료
├── backup\                기존 도구를 고칠 때 이전 판 보관
├── README.md              사용법
├── CHANGELOG.md           변경 이력(## YYYY-MM-DD 형식, 새 판을 맨 위에)
└── SKILL.md               결과물에 Claude 스킬이 포함될 때 정본
```

- **기존 도구를 확장할 때:** 고치기 전에 원본을 `backup\`에 날짜를 붙여 복사하고, 기존 사용법이 깨지지 않게 옵션으로 추가한다.
- **Python:** 이 PC의 기존 도구처럼 `py -3.12`를 쓴다. 다른 PC에 배포해야 할 때만 가상환경과 설치 스크립트(run.bat)를 만든다.
- **비밀키:** `.env`에만 두고 코드·로그·README에 쓰지 않는다. 키 값은 사용자가 직접 넣는다.
- **git:** `J:\AI 자료`가 git 저장소이므로 출력물·대용량·비밀 파일이 커밋되지 않게 `.gitignore`를 확인한다. 커밋은 사용자가 요청할 때만 한다.

## B3. Smoke Test 먼저

외부 연동(API·웹사이트·한글 COM·외부 프로그램)이 있으면 코드를 본격적으로 쓰기 전에 실제로 1건 실행한다. 결과는 `02_타당성_SmokeTest.md`의 해당 항목에 `PASS / FAIL / 미실시`와 날짜, 실제 응답 요지로 적는다. FAIL이면 설계를 고칠지 사용자와 정한 뒤 진행한다.

## B4. 작업별 구현 순서

작업 하나마다 아래를 반복한다. 끝나지 않은 작업을 두고 다음 작업으로 넘어가지 않는다.

1. 구현한다. 설계서의 Adapter 분리, 원본 저장과 AI 처리 분리 원칙을 지킨다.
2. 사용자가 준 견본 자료로 실제 실행한다. 견본이 없으면 임의로 만든 자료로 "완료"라고 하지 않는다.
3. 결과물을 직접 열어 확인한다. HWP·엑셀·PDF는 내용을 읽어 보고, 한글 결과는 글자 깨짐과 서식을 확인한다.
4. `05_제작기록.md`에 상태와 시험 결과를 적는다.

같은 방법으로 세 번 실패하면 더 밀어붙이지 말고 원인과 대안을 정리해 사용자에게 묻는다.

## B5. P0 시연과 확인

P0가 끝나면 실제 업무 자료 1건으로 처음부터 끝까지 돌리고, 결과와 걸린 시간을 사용자에게 보여 준다. 사용자 피드백은 제작 기록의 "결정·변경"에 적는다. 확인을 받은 뒤 P1으로 넘어간다.

## B6. P1 이후

B4~B5를 반복한다. 사용자가 범위를 바꾸면 설계서의 해당 절과 4절(자동화 범위)도 함께 고친다.

## B7. 인수 테스트

`04_인수테스트.md`의 항목을 실제로 실행하고 항목마다 `PASS / FAIL / 미실시(이유)`를 적는다.
- `.cmd`는 사용자가 더블클릭하는 방식과 같게 새 CMD 창(`cmd /c`)으로 실행한다. 한글 경로, 오류가 났을 때 창이 유지되는지도 확인한다.
- 잘못된 입력, 빈 폴더, 외부 연결 실패, AI 실패 상황에서 프로그램이 멈추지 않고 안내하는지 확인한다.
- 실행하지 못한 항목은 `미실시`로 두고, 완료 보고에 그 목록을 그대로 적는다.

## B8. 마무리

1. `README.md`에 무엇을 하는 도구인지, 실행 방법(더블클릭·명령어), 입출력 위치, 설정, 자주 나는 오류를 적는다.
2. `CHANGELOG.md`에 `## YYYY-MM-DD` 형식으로 무엇을 만들었고 무엇을 시험했는지 적는다. 카탈로그 스크립트는 이 형식만 읽는다.
3. **결과물에 Claude 스킬이 포함되면:**
   - 정본 `SKILL.md`는 도구 폴더에, 사용 사본은 `C:\Users\user\.claude\skills\<스킬명>\SKILL.md`에 둔다.
   - description에는 사용자가 실제로 말할 법한 요청 문장을 3~5개 넣는다.
   - 본문에는 스크립트 경로, 실행 명령, 실행 후 보고할 내용, 주의사항(원본을 건드리지 않음, 덮어쓰기 전에 물어봄 등)을 넣는다.
   - 저장한 뒤 이 세션의 스킬 목록에 올라오는지 확인한다.
4. 카탈로그를 갱신하고, 카탈로그는 불일치를 알려 줄 뿐 자동으로 고치지 않는다고 사용자에게 알린다.
   ```powershell
   python "J:\AI 자료\Claude outputs\skill_catalog.py"
   ```
5. 도구 위치, 실행 방법, 시험하지 못한 항목을 메모리에 기록한다.
6. 완료 보고에는 만든 파일, 시험 결과(PASS/FAIL/미실시), 남은 문제, 사용자가 직접 할 일(키 입력, 설치 등)을 적는다.

## 사용자 승인을 받고 진행할 것

아래는 실행하기 전에 무엇을, 왜 하는지 말하고 승인을 받는다.

| 행동 | 이유 |
|---|---|
| 패키지·프로그램 설치(pip, Ollama, FFmpeg 등)와 버전 변경 | 기존 도구가 깨질 수 있다. 예: av 19.x는 faster-whisper와 충돌 |
| 기존 도구·스킬 파일 수정 | 지금 쓰는 업무 흐름에 영향 |
| 유료 외부 API 호출, 대량 호출 | 비용 발생 |
| 자료를 외부 AI 서비스로 보내는 것 | 보안등급([internal] 등) 확인 필요 |
| 레지스트리·시스템 설정 변경, 예약 작업 등록 | 시스템 전체에 영향 |
| 파일 삭제·덮어쓰기 | 되돌리기 어려움 |
| git 커밋·푸시 | 사용자가 요청할 때만 |

API 키·비밀번호는 Claude가 입력하지 않는다. 사용자에게 `.env`에 직접 넣어 달라고 안내한다.
