4. 쓰기(다음 네 가지만)
 a. 0 wiki/분석/{오늘 YYYY-MM-DD} lint 보고.md를 새로 만든다. 같은 이름의 파일이 있으면 아무것도 쓰지 말고 그 사실을 답하고 끝낸다. 머리말은 직전 lint 보고서와 같은 필드를 쓴다(type: 분석, title, sources, created, updated, status: draft, reviewed_at 빈값, domain, tags: [분석, lint]). 법령 MCP 조회는 sources에 "web: https://www.law.go.kr …(법령 MCP 경유 조회, 확인일 YYYY-MM-DD)" 형식으로 적는다. 본문은 점검 방법 → 점검 결과 요약 표 → 절별 상세 → 제안 표(번호, 제안, 성격) 순서로 쓴다. 제안은 실행하지 않는다. internal 자료의 내용은 옮기지 않고 페이지 이름만 적는다.
 b. 0 wiki/분석/_index.md에서 마지막 "lint 보고" 줄 바로 아래에 "- [[{날짜} lint 보고]]: 월간 정비(B). {한 줄 요약} (draft)" 한 줄을 넣는다. 다른 줄은 고치지 않는다.
 c. 0 wiki/log.md: 쓰기 직전에 끝 50줄만 확인하고 파일 끝에 붙인다. 전체를 다시 쓰거나 분할하지 않는다. 형식:
    ## [{날짜}] lint | 월간 정비(B, 예약 작업) | {지금 사용 중인 모델명}

    - 근거: A 결과 파일명, 법령 MCP 조회 도구와 기준(MST, 시행일). 국가법령정보센터 웹 화면과의 동일성은 확인하지 않았음
    - 주요 발견: (한두 줄)
    - 세션: 예약 작업(원격 셸 또는 로컬, 삭제 제한)이므로 커밋하지 않음
    - 커밋 대상 파일: 0 wiki/분석/{날짜} lint 보고.md, 0 wiki/분석/_index.md, 0 wiki/log.md
    - 커밋 메시지 초안: lint: {날짜} 월간 정비 보고
