## 결론

CDN(Content Delivery Network)을 이용하면 국내에서 접속차단된 불법 사이트를 다시 이용할 수 있도록 만들거나, 새로운 주소로 재개설하는 데 기술적으로 도움이 될 수 있습니다. 그러나 CDN 자체가 폐쇄된 사이트를 복구해 주는 것은 아닙니다.


특히 한겨레 기사에 등장하는 사례는 기존 운영자가 CDN 사업자에게 복구를 요청한 사례가 아닙니다. 기사에서는 기존 운영자들이 검거된 뒤 다른 운영자가 기존 사이트의 명칭을 도용한 사칭 사이트를 개설했다고 명시하고 있습니다.

![](https://www.google.com/s2/favicons?domain=https://www.hani.co.kr&sz=32)

한겨레

따라서 기사에서 말하는 CDN을 통한 접속차단 우회와 사칭 사이트의 재등장은 구별해 이해해야 합니다.

## 1. CDN을 이용해 차단된 사이트가 다시 나타나는 원리

CDN을 사용하는 사이트의 일반적인 데이터 전달 구조

CDN은 원래 웹사이트의 접속 속도를 높이고 서버의 부하를 분산하는 기술입니다. 하지만 이러한 특성이 불법 사이트 운영에도 악용될 수 있습니다.

첫째, 기존 도메인이 차단되어도 해외 원본 서버가 유지되는 경우입니다.

국내 ISP에 특정 사이트의 접속차단을 요구하더라도 해외 원본 서버의 데이터까지 삭제되는 것은 아닙니다. 운영자가 다른 도메인을 이용해 같은 서비스를 다시 제공할 수 있고, CDN은 그 과정에서 데이터를 전달하는 역할을 합니다.

둘째, CDN을 이용하면 기존 접속차단 기술의 실효성이 떨어질 수 있습니다.

이용자와 해외 원본 서버 사이에 CDN이 위치하면 통신 경로와 접속 정보가 기존의 직접 연결 방식과 달라집니다. 특히 암호화된 통신 기술까지 사용하면 ISP가 차단 대상 사이트를 식별하기 어려운 경우가 발생합니다.

정부도 2026년 9월 22일 보도자료에서 CDN을 이용한 관문망 차단 우회와 QUIC·ECH 등 암호화 기술의 확산을 기존 차단 체계의 한계로 명시했습니다.

셋째, 원본 서버를 실제로 폐쇄했더라도 별도 백업이 존재하면 재개설될 수 있습니다.

이 경우 새로운 호스팅 서비스를 확보하고 보관 중인 데이터를 다시 배치해야 합니다. CDN은 재개설된 사이트의 콘텐츠를 전달하는 데 활용될 수 있지만, 삭제된 원본 데이터를 자동으로 복원하는 수단은 아닙니다.

즉, 기사가 설명하는 문제는 CDN의 복구 기능이 아니라 원본 데이터를 보존한 채 국내 접속차단을 우회하거나 새로운 전달 경로를 확보할 수 있다는 점입니다.

## 2. CDN 사업자가 기존 운영자의 요청을 받아 사이트를 복구해 주는가?

일반적인 CDN 서비스에서는 운영자가 CDN 사업자에게 별도로 '차단된 사이트를 복구해 달라'고 요청하는 구조가 아닙니다.

운영자는 CDN 사업자와 서비스 이용계약을 체결하고 자신의 웹사이트에 CDN 서비스를 적용합니다. 국내 ISP가 접속을 차단했다고 해서 CDN 사업자와 체결한 서비스 계약까지 자동으로 해지되는 것은 아닙니다.

반대로 CDN 사업자가 불법정보 유통을 이유로 서비스를 중단하면 그 CDN을 통한 전달은 제한됩니다. 운영자가 다른 업체를 통해 서비스를 재개하려면 원본 서버 또는 복구 가능한 데이터가 남아 있어야 합니다.

CDN 업체인 Cloudflare의 정책도 참고할 만합니다.

Cloudflare는 자사의 일반적인 CDN·역방향 프록시 서비스와 원본 콘텐츠를 직접 호스팅하는 서비스를 구분합니다. 일반 CDN 서비스에서는 다른 업체의 서버에 저장된 원본 콘텐츠를 직접 삭제할 수 없다고 설명합니다.

다만 아동 성착취물과 관련하여 특정 조건에서는 서비스 제공을 중단할 수 있으며, 자체 호스팅 서비스에 저장된 불법 콘텐츠에 대해서는 접근차단 또는 삭제 조치를 취할 수 있다고 밝히고 있습니다.

## 4. 그렇다면 현재 남아 있는 실질적인 한계는 무엇인가?

문제는 CDN 사업자에 대한 규제가 전혀 없다는 것이 아니라, 규제 대상과 원본 서버의 통제 가능성이 서로 다르다는 점입니다.

CDN에 대한 접근제한 조치가 이루어지더라도 해외 원본 서버에 콘텐츠가 남아 있다면 재유포 가능성이 존재합니다. 또한 도메인이 변경되거나 새로운 사이트가 등장하면 신규 대상을 식별하고 차단하는 과정이 추가로 필요합니다.

## 종합 판단

질문하신 상황은 다음과 같이 정리하는 것이 정확합니다.

운영자가 CDN 사업자에게 폐쇄된 사이트의 복구를 요청하는 구조가 아니라, 불법정보가 해외 원본 서버 등에 남아 있는 상태에서 CDN을 콘텐츠 전달 수단으로 활용하기 때문에 국내 접속차단만으로 사이트 운영과 재개설을 근본적으로 차단하기 어려운 구조입니다.

현재는 CDN 사업자에게도 일정한 법적 의무와 제재 규정이 있으며, 실제 접근제한 조치가 시행되고 있습니다.

따라서 기사 내용을 정책적으로 해석한다면, 핵심은 CDN 사업자에 대한 제재 근거의 부재가 아니라 국내 CDN 접근제한의 실효성, 해외 원본 서버에 대한 삭제·폐쇄 권한의 한계, 도메인 변경 및 신규 사이트 발생에 대한 지속적인 대응 필요성에 있다고 보는 것이 타당합니다.

## 1. 핵심 원리: CDN을 이용하면 국내 접속차단을 피할 수 있는 이유

가장 중요한 것은 CDN이 이용자와 해외 원본 서버 사이에 별도의 콘텐츠 전달 경로를 만든다는 점입니다. 특히 국내 CDN 서버에 콘텐츠가 저장되어 있으면, 이용자가 해외 원본 서버에 직접 접속하지 않고도 해당 콘텐츠를 받을 수 있습니다.

국내 접속차단은 전통적으로 해외 불법사이트로 향하는 통신을 국내 인터넷서비스사업자(ISP)의 국제관문망에서 식별하고 차단하는 방식으로 운영되어 왔습니다.

그런데 CDN이 중간에 개입하면 두 가지 문제가 발생할 수 있습니다.

- 국내 CDN 서버에서 콘텐츠를 바로 제공하면 해외 원본 서버까지 연결할 필요가 없어, 국제관문망 중심의 차단 체계가 적용되지 않는 경로가 생길 수 있습니다.
    
- CDN을 통해 해외 원본 서버에 연결하면, 이용자가 직접 접속하는 서버의 IP 주소가 원본 서버가 아닌 CDN 서버의 주소로 나타납니다. 따라서 원본 서버의 IP 주소만을 기준으로 차단하는 방식은 한계가 있습니다.
    

다만 CDN을 사용한다는 사실만으로 모든 접속차단을 우회하는 것은 아닙니다. 도메인 이름을 식별하는 SNI 차단이나 CDN 사업자 자체의 접근제한 조치가 적용되면 CDN을 경유하더라도 접속이 차단될 수 있습니다.

개념도입니다. B의 경우에도 국내 ISP나 CDN 서버에서 차단할 수 있습니다. 그림은 국제관문망을 통과하지 않는 국내 캐시 전송 경로의 차이를 나타냅니다.

여기서 중요한 것은 해외 원본 서버가 그대로 살아 있어도 국내 CDN 서버가 콘텐츠의 사본을 보관하고 전달할 수 있다는 것입니다.

CDN에는 보통 다음 두 가지 동작이 있습니다.

- Cache Hit(캐시 적중): 요청받은 영상이나 이미지가 CDN 서버에 이미 저장되어 있다면, 해외 원본 서버에 요청하지 않고 CDN 서버가 직접 전달합니다.
    
- Cache Miss(캐시 미적중): CDN 서버에 해당 데이터가 없으면 해외 원본 서버에서 가져와 전달합니다. 캐시 정책에 따라 사본을 저장하기도 합니다.
    

또한 CDN은 데이터를 저장하지 않는 요청도 원본 서버로 중계할 수 있습니다. 따라서 모든 콘텐츠가 CDN에 저장되어 있는 것은 아닙니다.

![](https://www.google.com/s2/favicons?domain=https://developers.cloudflare.com&sz=32)

Cloudflare Cache (CDN) docs

+1

이것이 정부가 국내 CDN 사업자의 임시저장 서버를 별도의 규제 대상으로 삼은 기술적 배경입니다.

## 3. CDN을 이용하면 해외 원본 서버의 위치도 감출 수 있습니다

CDN의 두 번째 역할은 **역방향 프록시(Reverse Proxy)**입니다.

예를 들어 불법 사이트가 해외 서버 `203.0.113.10`에 저장되어 있다고 가정하겠습니다. 이 주소는 설명을 위한 가상 IP입니다.

CDN을 사용하지 않으면 이용자는 해당 서버로 직접 연결됩니다.

반면 CDN을 사용하면 사이트의 도메인을 조회했을 때 원본 서버가 아니라 CDN 사업자의 IP 주소가 반환될 수 있습니다.

이 경우 국내 ISP가 확인하는 연결 목적지는 CDN 서버입니다. 실제 원본 서버는 CDN 사업자 뒤에 위치하게 됩니다.

![](https://www.google.com/s2/favicons?domain=https://developers.cloudflare.com&sz=32)

Cloudflare Reference Architecture docs

이 구조에서는 원본 서버의 IP를 차단하는 것만으로는 충분하지 않을 수 있습니다.

그러나 여기에는 중요한 제한이 있습니다.

IP 주소를 숨겼다고 해서 도메인 이름까지 자동으로 숨겨지는 것은 아닙니다.

국내 ISP가 특정 도메인을 SNI 방식으로 차단하고 있고, 접속 과정에서 해당 도메인이 평문으로 노출된다면 CDN을 경유하더라도 그 도메인의 접속을 차단할 수 있습니다.

따라서 CDN의 효과는 단순히 '서버 IP를 가린다'는 데 그치지 않습니다. CDN이 제공하는 네트워크 구조와 암호화 기술이 기존 접속차단 방식의 한계와 맞물리는 것이 문제입니다.

## 4. SNI 암호화 기술과 결합하면 차단이 더욱 어려워질 수 있습니다

여기서 등장하는 기술이 ECH(Encrypted Client Hello)입니다.

국내에서는 2019년부터 HTTPS 사이트에 대한 SNI 기반 접속차단이 도입됐습니다. SNI는 이용자가 어떤 도메인에 접속하려는지 서버에 알려주는 정보입니다.

기존 방식에서는 ISP가 이 정보를 확인하여 차단 대상 도메인인지 판단할 수 있었습니다.

ECH가 활성화된 CDN 서비스를 사용하는 사이트에 접속하면, ISP는 이용자가 해당 CDN 네트워크에 연결하는 것은 확인하더라도 실제로 어느 도메인에 접속하는지는 식별하기 어려울 수 있습니다.

CDN이 여러 정상 사이트와 불법 사이트를 같은 IP 주소에서 서비스하는 경우에는 IP 주소 전체를 차단하면 정상 사이트까지 영향을 받는 문제가 있습니다.

다만 ECH는 CDN의 기본 기능이 아니라 별도의 암호화 기술입니다. 또한 DNS 질의 등 다른 경로에서 도메인 정보가 노출되거나 CDN 사업자가 직접 접근제한을 시행한다면 차단이 가능합니다.

정부도 2026년 9월 22일 발표에서 QUIC와 ECH 등 새로운 통신 기술의 확산으로 기존 접속차단 체계에 한계가 발생하고 있다고 밝혔습니다.

## 5. 접속차단 후 새로운 도메인으로 다시 나타나는 과정

이번에는 실제 불법 사이트가 재등장하는 상황을 가정하겠습니다.

어떤 불법 사이트가 `site-a.example`이라는 주소를 사용하고 있고, 해외 원본 서버에 영상과 사이트 운영 프로그램이 저장되어 있다고 가정합니다.

방송미디어통신심의위원회가 `site-a.example`에 대해 접속차단을 결정하더라도, 이것만으로 원본 서버가 삭제되지는 않습니다.

이때 기존 운영자가 원본 서버와 운영 권한을 유지하고 있다면 다른 도메인인 `site-b.example`을 통해 같은 서비스를 제공할 수 있습니다.

이 구조에서 CDN의 역할은 다음과 같습니다.

|구분|CDN의 역할|
|---|---|
|원본 데이터 유지|직접 보관하는 것이 아니라 기존 서버의 콘텐츠를 전달|
|새로운 도메인 사용|새 주소에서도 기존 서버의 콘텐츠를 제공하는 전달망으로 활용 가능|
|원본 서버 IP 비노출|이용자에게 CDN 서버의 IP를 제공|
|국내 접속 경로|국내 캐시 서버를 통해 콘텐츠를 직접 제공할 수 있음|
|접속차단 식별|암호화 기술과 결합할 경우 기존 SNI 식별이 어려워질 수 있음|

여기서 새로운 도메인으로 사이트가 등장하는 것은 CDN 자체의 기능이 아닙니다. 도메인 변경과 CDN 활용은 서로 다른 행위이지만 함께 사용될 수 있습니다.

또한 특정 도메인의 국내 접속차단은 보통 기존 도메인에 대한 조치입니다. 새로운 도메인에 대해 기존 차단 조치가 자동으로 동일하게 적용된다고 단정할 수는 없습니다.

반면 원본 서버가 압수·삭제되고 운영 데이터까지 확보되지 않은 경우라면 단지 CDN만으로 기존 사이트를 다시 운영할 수는 없습니다. 일시적으로 저장된 캐시 데이터가 남을 가능성은 있지만, 그것이 사이트 전체를 계속 운영할 수 있다는 의미는 아닙니다.

## 6. 현재 정부가 CDN 단계의 접근제한을 별도로 시행하는 이유

이러한 문제 때문에 정부는 기존 ISP 국제관문망 차단에 더해 CDN 사업자에게 직접 접근제한을 요구하는 방식도 사용하고 있습니다.

실제로 2026년 9월 22일 정부 발표에 따르면, 심의·의결된 디지털성범죄 불법사이트 443개 중 380개에 대해 CDN 단계의 접근제한 조치가 완료됐습니다.

즉, CDN 사업자가 자신의 서버를 통해 전달하거나 임시 저장하는 불법정보를 식별하여 접근을 제한하도록 하는 것입니다.

![](https://www.google.com/s2/favicons?domain=https://m.korea.kr&sz=32)

대한민국 정책브리핑

접속차단 정책의 세 가지 수준을 구분하면 다음과 같습니다.

|조치 수준|주요 대상|남는 한계|
|---|---|---|
|ISP 접속차단|국내 이용자의 접속 경로|차단 경로 밖에 있는 원본과 CDN 캐시|
|CDN 접근제한|특정 CDN을 통한 콘텐츠 제공|다른 CDN이나 해외 원본 서버|
|원본 서버 폐쇄·삭제|실제 사이트 운영 기반과 저장된 데이터|별도 백업, 다른 서버에 저장된 사본|

이 가운데 원본 서버와 불법 콘텐츠의 복제본까지 제거하는 조치가 재유포 방지에 더 근본적인 효과를 갖습니다. 그러나 서버와 백업이 해외에 있거나 여러 사업자에 분산되어 있다면 법 집행과 국제공조 문제가 발생합니다.

## 최종적으로 구분해야 할 사항

이번 한겨레 기사에서 말하는 CDN 악용은 기술적으로 이해할 수 있는 문제입니다. 특히 국내 CDN의 캐시 전송 경로와 원본 서버 IP를 가리는 구조는 기존 차단 방식의 실효성을 떨어뜨릴 수 있습니다.

그러나 기사에 등장하는 사칭 사이트가 실제로 어떤 CDN을 이용했고, 어떤 기술로 접속차단을 회피했는지는 기사만으로 확인할 수 없습니다. 이러한 기술적 가능성을 실제 사건에서 사용된 수법으로 단정해서는 안 됩니다.

따라서 정책적으로 가장 정확한 표현은 다음과 같습니다.

> 불법 성착취물 사이트는 해외 원본 서버에 저장된 콘텐츠를 CDN을 통해 국내 이용자에게 전달할 수 있으며, 국내 임시저장 서버를 이용하거나 암호화 기술을 활용하는 경우 기존 국제관문망 중심의 접속차단 방식만으로는 접근을 충분히 제한하기 어려울 수 있다. 또한 원본 서버가 유지되는 한 도메인을 변경하여 사이트를 재개설할 가능성이 있으므로, CDN 단계의 접근제한과 해외 원본 서버에 대한 삭제·폐쇄 조치를 병행할 필요가 있다.

특히 실무적으로는 ① CDN 경유로 인한 차단 사각지대, ② 도메인 변경에 따른 신규 차단 필요성, ③ 원본 서버 미삭제에 따른 재유포 가능성을 별개의 문제로 구분하는 것이 중요합니다.
