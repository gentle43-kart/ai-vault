# 열린 확인 항목 분류 (2026-11-12)

위키 페이지 "추가 확인 필요" 절의 열린 항목(미완료 체크박스)을 검토 유형별로 나누고, 같은 문장이 반복되는 묶음을 일괄 처리 후보로 정리했다. [[2026-11-11 lint 보고]] 5절의 분류를 이어받되, 그 뒤 위원회 규칙 제8~12호 등재본 대조(제안 ①)로 항목이 줄어든 현재 상태를 기준으로 다시 셌다.

- 대상·조건·단위: `wiki_lint.py` v1.6이 내는 `_open_items`(@Inbox·@clippings·@templates·log 제외)의 열린 항목. 단위는 항목(체크박스 한 줄)이다.
- 방법: `script: Claude outputs/open_items_classify.py` v1.0. 항목 문장에서 "(근거: …)" 앞부분을 먼저 보고, 맞는 유형이 없으면 근거 부분까지 본다. 키워드로 처음 맞는 유형 하나에만 넣는 기계 분류이므로 경계 항목은 다른 유형으로 볼 수도 있다. 유형은 처리 순서를 정하려는 것이며 항목의 내용을 판단한 것이 아니다.
- 검증값: 열린 항목 731개(389쪽). 2026-11-11 보고의 1,007개에서 정보통신망법 제21500호 항목 40개를 닫고 2개를 더해 969개가 되었고, 그 뒤 규칙 제8~12호 등재본 대조 항목 238개가 닫혀 731개가 되었다(969 − 238 = 731).
- 이 페이지는 internal 자료의 내용을 옮기지 않고 페이지 이름만 적으므로 `classification`을 적지 않았다.

## 3. 시한이 지났거나 사용자 확인을 기다리는 항목

- 시행 예정이던 법률의 시행일이 지나 지금 확인할 수 있는 항목: [[광고성 정보 전송·게시(통신심의)]], [[해킹·바이러스정보(통신심의)]]의 "정보통신망법 … 법률 제21500호(시행 2026. 10. 1.·2027. 4. 1.)에 따른 개정 여부". 2026-11-11 후속 처리는 조문 페이지만 갱신했으므로 이 두 쟁점 페이지의 항목은 남아 있다. → 해소(2026-11-12): 법령 MCP로 제21305호·현행·시행예정본을 비교해 두 쪽에 반영하고 닫았다(제50조의4 제4항 개정, 제71조 제1항 제13호의2 신설).
- [[방송법 제83조]], [[방송법 제86조]]: 법령 MCP 조회본과 문언이 일치함은 확인했고 `verified_at` 기입만 사용자 확인을 기다린다고 적혀 있다. → 해소(2026-11-12): 법령 MCP 현행본과 다시 대조해 일치함을 확인하고, 사용자 확인에 따라 `verified_at`을 채웠다.
- [[자살유발정보(통신심의)]]: 자살예방법 제19조의5 시행(2026.11.12.) 뒤의 처리 방식 항목은 시행일이 오늘이므로 이후 확인 대상이 된다.

## 4. 처리 순서 제안 (사용자 확인 필요)

1. E 반복 묶음 68개: Claude Code로 통계 CSV를 일괄 집계해 닫는다(제안 ⑨).
2. 3절의 항목과 A 유형: 월간 정비(B)의 법령 현행성 점검 결과와 함께 법령 MCP로 대조해 닫는다. 내용 수정이므로 사용자 확인 뒤 C 단계에서 처리한다.
3. C 유형(반복 묶음 11개 포함): 통계 스크립트로 처리한다.
4. B 반복 묶음 11개: 닫을지 상시 항목으로 둘지 사용자가 정한다. → 처리(2026-11-12): 사용자 결정에 따라 11개 쪽 모두 4.1절 끝에 검색 한계 서술을 넣고 항목을 닫았다.
5. D 유형: 개정 이유서 등 원자료를 확보한 범위에서 처리하고, 나머지는 데이터 공백으로 남긴다.

전체 목록은 `python "Claude outputs/open_items_classify.py" --list A`처럼 유형 기호를 주어 출력한다.
